# MVP decisions and evidence

Planning decision: 13 November 2026. This backlog selects the saved PDF-checkout candidate for development planning under the user's current mission. It does not authorize application implementation, deployment, transactions or interaction with real merchant checkouts.

- The saved scenario recommends Jev as a candidate, not a requirement. The [official Jev API](https://docs.typesafe.ai/api/system-one) documents typed questions. This MVP needs extraction of variable amounts, intervals, trial durations and evidence text as well as classification. One structured-output Gemini call avoids adding a second extractor. This is an architectural judgment, not a comparative model benchmark.
- The source's 3–4-hour build sketch is aspirational and predates a provider/stack check. Sizes below are relative development estimates: S = bounded small change; M = cohesive component with failure cases; L = requires splitting. No delivery guarantee is inferred.
- The source permits fresh subscription consent if subscription execution is supported. This MVP supports read-only review and return to one-off checkout. Subscription enrollment and its new consent flow are optional future work, so there is no override action to implement now.

Consumer complaints motivate the saved scenario but are not reverified here. No assertion of proven fraud, a desktop victim or an actual last-second transaction swap is made. Prices, merchant, seven-day trial and injected state changes are fictional fixture choices.

No provider SDK, schema library or second model is planned; use an explicit validator for this small fixed response contract.

## Shared implementation contract

One Node process owns a single demo session in memory. Serve an allowlisted set of static files and fixed JSON routes on `127.0.0.1`. Reloading can reconnect to that session; an explicit reset or process restart clears its intent, pending checks, grants and outcomes. No persistence or multi-user service is required.

- **Independent intent:** `intentId`, intent revision, synthetic document ID, action `convert-one-document`, chosen merchant ID, currency `USD`, maximum upfront amount in integer cents (default 200), billing scope `one_off_only`. Only explicit Safety Belt confirmation creates/revises it. Merchant/model text is untrusted data and cannot modify it.
- **Checkout snapshot:** checkout ID, monotonically increasing revision, merchant ID/display name, document ID/action, exact public disclosure text, and the immutable commitment that the fixture would execute: upfront cents/currency, billing kind (`one_off`, `recurring`, `unknown`), renewal cents/interval, and trial duration if applicable. Keep expected evaluation labels separately and never include hidden commitment fields or labels in model input. Every change to these fields or disclosure text increments the revision, including a change away and back.
- **Interpretation:** upfront cents/currency, merchant display name, billing kind, renewal cents/interval, trial duration, evidence status (`clear`, `missing`, `contradictory`, `uncertain`, `unsupported`) and exact supporting quotations. Money is a nonnegative safe integer in cents; unsupported representations pause. Require evidence for a one-off claim as well as recurring terms. Validate required fields, enums, nullability and conditional fields; reject unsupported/extra fields and quotations absent from the snapshot. Treat disclosure text as data, with no tools or authorization capability. Cross-check extracted material fields against the owned fixture's execution commitment; disagreement requires clarification, never an allow.
- **Decision:** `ALLOW`, `CONFLICT` or `CLARIFY`, with stable reason codes, intent/snapshot revisions and inspectable evidence. Price, currency, merchant, action/document scope and recurrence are deterministic checks. Unknown, invalid, failed or stale interpretation cannot mint a grant. Only explicit one-off terms matching scope and costing at most the approved cap may allow.
- **Grant:** service-generated opaque single-use ID bound to session, intent ID/revision, checkout ID/revision and all material commitment fields. The browser cannot mint or edit it. A changed intent, snapshot, reset or completed action invalidates it. A late model response must match the current intent and checkout revisions before it can affect a decision or grant.
- **Execution boundary:** all supported button, Enter and direct JSON submit requests reach the same service handler. Immediately before simulated execution, compare the current state and grant, consume the grant and update outcome state synchronously with no `await` between check/consume/side effect. Execute the exact captured commitment, not reread mutable state. This single-process in-memory critical section is sufficient; no distributed lock or database is needed.
- **Observable truth:** service-owned attempted-submit count, execution count, payment records, subscription records and conversion status; the latter states, not a model answer or UI banner, determine success. The allowed route creates one USD 1 payment and completes the synthetic conversion, with zero subscriptions. Conflicts/clarifications create no payment/subscription/conversion effects. Count attempts separately from executions. At most one payment per demo intent/document; reset starts a new run.
- **Minimum privacy/security:** only the public merchant name and disclosure text go to the fixed provider endpoint, never intent, hidden labels, document contents or payment/personal fields. Key stays in service environment and is ignored by Git. Do not serve environment files or log keys/request bodies. Reject unexpected Host/Origin and cross-origin mutation requests, disallow permissive CORS, limit JSON body size, validate route inputs and render evidence as text. Provider timeout is finite (10 seconds), errors are sanitized and fail closed. Model output never becomes executable HTML or code.

These controls establish the boundary of one owned demo checkout. They do not authenticate third-party merchant backends or reveal undisclosed future charges.
